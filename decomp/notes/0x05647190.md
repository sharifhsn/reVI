# 0x05647190

19 bytes, and the whole body is a jump over a load:

```
sub   rsp, 28h
xor   al, al
jmp   short 0xd
movzx eax, byte ptr [rsp+38h]   ; caller's stack argument
add   rsp, 28h
ret
int3
```

By default it returns 0 and never touches the argument; the load at `[rsp+38h]`
is only reached through a jump from outside this extent, i.e. from a caller's
loop or another entry. `[rsp+38h]` after a 0x28 frame is the caller's
**fifth** argument slot (0x28 return + 0x20 shadow = 0x48; 0x38 is shadow+0x18,
the fifth integer slot, which is stack-passed in x64).

So the shape is:

```cpp
bool f(/* four register args */, bool fifth) { return false; /* then jump back in to load fifth */ }
```

## Open

* Which path jumps to +0x8? Without a caller the fifth argument's meaning is
  unknown. Grep callers that `jmp` into 0x08 rather than calling.
* Return is `al` (bool); the `xor al,al` default means "false unless the
  external path re-enters".
