# 0x0569f0

41 bytes. A counted wait: resolves the wait function once into `rbx`, then calls
it `count` times with an infinite timeout.

## Original

```
push rsi ; push rdi ; push rbx ; sub rsp,0x20
rbx = [0x673d130]        cached function pointer
esi = edx                count
rdi = rcx                handle
.loop:
rcx = rdi ; edx = 0xffffffff
call rbx
dec esi
jne .loop
epilogue
```

`[0x673d130]` holds a pointer to `WaitForSingleObject`'s IAT slot, so the
function is a plain `while (count--) WaitForSingleObject(handle, INFINITE)`.

## Reading

```cpp
typedef unsigned long (__stdcall *wait_fn)(void *, unsigned);
extern wait_fn g_wait; /* 0x673d130 */
void f(void *handle, unsigned count) {
    for (; count != 0; --count)
        g_wait(handle, 0xffffffff);
}
```

## Evidence

`REVI_STUBS=1`, entering at the function start:

| count | stub calls |
|---:|---:|
| 3 | 3, each `(handle, 0xffffffff)` |
| 1 | 1 |

Loop count and arguments are confirmed by execution.

## Codegen

38%, 17 instructions against 18. Same operations in the same order; MSVC picks
`rbx` for the cached pointer where we get `rsi`, and spills two registers instead
of pushing three. Two shapes tried.

## Open

* Reached from the reservation handler `0x2a1af0` (`jmp` at `+0xF0`), so it is
  part of the wait side of the slot protocol.
* Who calls it with a count above 1? The count is the interesting parameter.
