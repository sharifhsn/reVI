# 0x043c4140

0x228 bytes. Body of one subrender worker thread. It claims a slot, then loops
waiting for work, running each item under the item's own semaphore, and exits
when the queue is drained.

```
sub_144fab4b0(4)
v5 = slot * 0x40
if (tls2->inited)  tls->slot = slot;                    // +0x1294
else { init(); tls->slot = slot; if (!was_inited) init(); }
tls->in_use = 1;                                        // +0x1110
if (!(record[slot].flags & 1)) return;                  // +0x30 of the record
loop:
  wait(record[slot].handle);                            // 0x149c3d678 + slot*0x40
  spin until (attention & 0xffffff) drains, cmpxchg      // 0x149c3be58
  lock(queue); item = queue[head]; --count; unlock()      // 0x149c3ba30/be4c/be50
  if (!item) break;
  ref = *item; cmpxchg(ref+1) and wait(ref->sem, 1)      // 0x2a1be0, SCARRY guard
  run(item, record[slot].a, record[slot].b)              // 0x1443c4370
  release(item[3])
exit:
  release(record[slot].obj)                              // +0x8
  if (record[slot].flags & 1) goto loop                  // re-check, loop again
```

The TLS byte at `+0x1294` is this thread's slot id — this function is its only
writer. `+0x1110` is an in-use flag. The record set is
`0x149c3d678 + slot*0x40` with the wait handle at `+0x0`, a released object at `+0x8`, the two run
arguments at `+0x20` and `+0x28` (`+0x28` only when a feature flag is set), and a
`flags` word at `+0x30`;
`slots` is `dat_149c3d660`, fixed at 5 by the pool initialiser.

## Reading

```cpp
void worker(unsigned slot)
{
    set_affinity(4);
    tls_ensure();
    tls->slot = slot;                    // the only write of +0x1294
    tls->in_use = 1;
    for (;;) {
        if (!(rec(slot).flags & 1)) return;
        wait(rec(slot).handle);
        attention_drain();               // 0x149c3be58, 0x100000000 units
        item = queue_pop();              // 0x149c3ba30 ring, head 0x149c3be4c
        if (!item) break;
        if (item->obj && ++item->obj->ref != INT_MIN) {
            wait(item->obj->sem, 1);     // item waits for its own producer
            --item->obj->ref;
        }
        run(item, rec(slot).a, rec(slot).b);
        release(item[3]);
    }
    release(rec(slot).obj);
    // falls back to the top when the slot is still marked active
}
```

## Evidence

Reached only as a thread start: one `LEA R15,[0x1443c4140]` in the pool
initialiser `0x043c38a0`, which creates five threads, formats `Subrender:%02u`
and passes each index.

The `WaitForSingleObject` veneer is `0x1784d0` (the import slot is
`0x146793b20`); the item wait is the shared `0x2a1be0`.

## Codegen

Drafted from the disassembly; the ring index wrap (`0x80`), the attention drain
and the refcount guard order are the parts to keep.

## Open

* Record layout beyond the measured offsets: `+0x0` handle, `+0x8` released
  object, `+0x20`/`+0x28` run arguments, `+0x30` flags. Bytes `+0x10`..`+0x18`
  are untouched here.
* `0x144fab4b0(4)` — affinity or priority, not read.
* The attention word `0x149c3be58` uses `0x100000000` units with a 24-bit count in
  bits 7..31; who raises it is not known.
