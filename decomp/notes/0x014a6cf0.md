# 0x014a6cf0

124 bytes. Fills one 12-byte entry of a 0x75-entry table: a value, a hit count,
and an encoded handle derived from a pointer. Bounds-checked, and the count can
be forced by the caller.

## Reading

```c
void f(struct entry *table, unsigned index, unsigned value, void *p, unsigned count)
{
    if (index > 0x74) return;
    struct entry *e = &table[index];
    e->value = value;
    e->count++;
    if (p) {
        unsigned chunk = *(unsigned char *)((char *)p + 0x30);
        struct chunk_desc *d = g_chunks[chunk];
        uint32_t offset = ((uintptr_t)p - d->base) / d->stride & 0x1ffff;
        e->handle = (chunk & 0x1f) << 17 | offset | (d->map[offset] << 5 & 0xffc00000);
    } else {
        e->handle = 0x1ffff;
    }
    if (count != 0xffffffff) e->count = count;
}
```

The handle is a 32-bit pack: 5 bits of chunk class, 17 bits of element offset,
10 bits lifted from a per-chunk table. `0x1ffff` is "no pointer". The table at
0x9717ad0 holds one descriptor per chunk class; each descriptor carries a base,
a stride and a map at +0x28.

## Codegen

18%, 37 instructions both, close in structure but MSVC chose different
callee-saved registers (rbx/r10/r11) and a different branch polarity, so almost
no instruction lines coincide. Two source shapes tried; the semantics are
pinned by the run, the placement is not.

## Open

* The chunk table and the handle format belong to streaming; naming
  `g_chunks` and the descriptor fields is the next step.
* Callers will show what `index` and `count` mean.
