# 0x05600570

210 bytes. The initialiser that `0x055ea040` tail-calls when the cookie still
matches. Publishes its argument and the argument's address to globals, seeds an
exception record with `0xC0000409` (stack buffer overrun), loads two routine
pointers, and runs two initterm-style calls.

## Sequence

```
mov [rsp+8], rcx            save the argument
sub rsp, 0x38
mov ecx, 0x17
call [IAT 0x1193600]        IsProcessorFeaturePresent(0x17)
test eax, eax
je  .continue
mov ecx, 2
int 0x29                    __fastfail(FAST_FAIL_STACK_COOKIE_CHECK_FAILURE)
.continue:
call 0x56006b4(&0x1808af0)
0x1808be8 = arg             saved value
0x1808b88 = &arg + 8        address of the slot after it
0x1808a60 = 0x1808be8       record points at the saved value
0x1808b70 = [rsp+0x40]      fifth argument
0x1808a50 = 0xC0000409      exception code
0x1808a54 = 1 ; 0x1808a68 = 1
[0x1808a70] = 2
[rsp+0x20] = [0x11e1ac8] ; [rsp+0x28] = [0x11e1ac0]   two code pointers
call 0x5600728(&0x9431d8)
ret
```

The two stack slots are handed to the second call implicitly, so the callee
reads them out of the caller's frame.

## Why the pair matters

`0x055ea040` is the guard: it compares against `__security_cookie` and only
reaches here while the cookie still holds the default. This function is the
real initialisation. Names pair as `cookie_check` → `cookie_init`.

## Evidence

**None from a run yet.** The first instruction calls through the IAT, and an
unmapped image has null IAT slots, so `revi call` faults immediately. This is
the clearest case for the harness: imports must be resolvable to stubs before
any startup body can execute.

## Codegen

39%. The store sequence lines up for the first half; then branch polarity,
`__fastfail` (target `int 0x29`, ours a call) and the two stack stores diverge.
`revi diff` now normalises `call [rip+import]` against a plain `call`, because an
unlinked object cannot produce the import form.

## Open

* The globals cluster in `.data` 0x1808a50..0x1808be8 and 0x9431d8 — one
