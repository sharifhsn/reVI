# 0x01662430

Factory behind `g_slots`. Creates one semaphore from a selector, and on an
out-of-memory failure trims the process working set and retries once before
gathering a trap.

```
push rsi ; sub rsp,0x30
esi = ecx                     selector
ecx = 0                       lpSemaphoreAttributes = NULL
r8d = 0x7fff                  lMaximumCount
r9d = 0                       lpName = NULL
[rsp+0x28] = 0x100002         dwDesiredAccess = SEMAPHORE_ALL_ACCESS|0x2
[rsp+0x20] = 0                dwFlags = 0
edx = esi                     lInitialCount = selector
call [IAT 0x6793ac8]          CreateSemaphoreExW
test rax,rax ; jnz .ret
call is_oom(0)                ; 0x2214c10, arg 0 = do not trap here
test al,al ; jz .trap
call mem_trim()               ; 0x2215fd0
   ... second CreateSemaphoreExW with the same six arguments ...
test rax,rax ; jnz .ret
call is_oom(0)
.trap:
int3
.ret:
rax = handle ; ret
```

## Reading

```cpp
void *f(unsigned selector)
{
    void *h = CreateSemaphoreExW(NULL, selector, 0x7fff, NULL, 0, 0x100002);
    if (h) return h;
    if (!is_oom(/*trap=*/false)) goto trap;      // 0x2214c10
    trim_working_set();                          // 0x2215fd0
    h = CreateSemaphoreExW(NULL, selector, 0x7fff, NULL, 0, 0x100002);
    if (h) return h;
    is_oom(false);
trap:
    __debugbreak();
}
```

The initial count is the selector, so selector N produces a semaphore that starts
with N counts. `0x5cabc40` only ever asks for 0, i.e. all five slots start
unavailable.

`0x2214c10(abort)` reads `GetLastError` and returns true only for
`ERROR_NOT_ENOUGH_MEMORY` (8) or `STATUS_NO_MEMORY` (0xC0000017); with `abort`
set it traps itself. `0x2215fd0()` is the memory path: `XMemIsToolsMemAvailable`,
two `XMemGetWorkingSetStatistics(0x2000000a)` calls around `0x4b40(ctx)`, then
`XMemTransferMemory(1, 0)` and `0x4d9dab0(ctx)`, trapping on any step that fails.

## Evidence

The full 0x7C-byte body is disassembled above; the two helpers are decompiled
from the image and read as the OOM pair.

Called with selector 0 under `REVI_STUBS`: traps at the first `int3`, because the
stubbed `CreateSemaphoreExW` returns NULL and the stub `GetLastError` does not
report OOM. The retry needs a real `CreateSemaphoreExW`, or a stub that fails once
and then succeeds with a non-zero handle and an `ERROR_NOT_ENOUGH_MEMORY`
`GetLastError`.

## Codegen

Drafted from the disassembly; the six-argument call with two stack slots and the
retry shape are the parts to keep exact.

## Open

* `XMemTransferMemory(1, 0)` — which pool and direction; the return is only used
  as success/failure.
* Selectors above 0 are never requested by `0x5cabc40`, so a semaphore with a
  non-zero initial count is unused so far. Max 0x7fff is the platform cap, not an
  observed value.
