# 0x00b4a090

Returns one half of a `double` member as a `float`.

## Original

```
push rax
vmovsd xmm0, [rcx+0x108]
mov    eax, edx
vmovsd [rsp], xmm0
vmovss xmm0, [rsp+rax*4]
pop    rax
ret
```

The double is spilled, then read back as `float[2]` at the caller's index. The
`push rax` reserves the 8-byte slot (and keeps the stack aligned); index 0 is
the low half, 1 the high half.

## Reading

```cpp
struct O { char pad[0x108]; double v; };
float f(O* o, unsigned i) { double d = o->v; return ((float*)&d)[i]; }
```

## Codegen

23 bytes both ways (`/O2 /GS- /arch:AVX2`), but not identical:

* ours `mov eax,edx` encodes as `8B C2`, the original uses `89 D0`
* ours spills to `[rsp+8]` with no `push`, the original `push rax` and uses `[rsp]`

Four source shapes (temp array, union, pointer cast, reference to the member)
all gave our shape, so this is a compiler-detail gap, not a reading error.
The `unsigned` index matters: `int` adds a `movsxd` and one byte.
