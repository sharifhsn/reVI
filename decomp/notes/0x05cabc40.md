# 0x05cabc40

79 bytes. Fills `g_slots[0..3]` with four results of one factory call. Each
call passes selector 0, so all four entries start as the same kind of handle.

```
sub rsp,0x28
g_slots[0] = sub_1662430(0)
g_slots[1] = sub_1662430(0)
g_slots[2] = sub_1662430(0)
g_slots[3] = sub_1662430(0)
ret
```

`g_slots` is 0x75defc0, the table the try-lock `0x00037a50` indexes by thread
slot, so this is the writer that makes the try-lock usable.

## Evidence

Runs but does not finish: under `REVI_STUBS` the factory reaches
`CreateSemaphoreExW` with a stubbed (zero) handle and traps on the failure path
(`SIGTRAP`, exit 133). That is the factory's assert, not a fault in this body.

## Codegen

83%, 15 instructions against 18; the store order and selectors match, the
register choice and one hoisted zero differ.

## Open

* `0x1662430` needs the real `CreateEventW` before this can complete.
* Only four slots are filled and the lock indexes by thread slot — the table is
  therefore per-thread-sized somewhere else, or the index is clamped.
