# 0x05cabc40

0x51 byte body. Fills the five slot handles from one factory call, each with
selector 0, so the table starts with five handles of one kind.

```
sub rsp,0x28
g_slots[0] = sub_1662430(0)
g_slots[1] = sub_1662430(0)
g_slots[2] = sub_1662430(0)
g_slots[3] = sub_1662430(0)
g_slots[4] = sub_1662430(0)
ret
```

`g_slots` is `0x75defc0`, a five-element array of 8-byte handles
(`0x75defc0..0x75defe0`), indexed by thread slot in the try-lock `0x00037a50`.
This body is the writer that makes the try-lock usable; `0x02483ad0` is its
closer.

Selector 0 is in ECX, i.e. the factory's first argument, and stays 0 at all five
sites.

## Evidence

Runs to completion with `REVI_STUB_RET=CreateSemaphoreExW=0x100`: the forty bytes
at `0x75defc0` come out as five `0x100` handles, exactly as the note reads, and
the vector asserts their hash.

Five stores, not four: `MOV [0x1475defc0/fc8/fd0/fd8/fe0], RAX` after five
`XOR ECX,ECX; CALL 0x1662430` pairs.

## Codegen

Drafted: element width is 8, so the declaration is `void *g_slots[5]`.
