# 0x00037a50

154 bytes. Opportunistically reserves a slot inside a packed 32-bit word with a
`lock cmpxchg` loop, then hands off to the slot's handler. Used as a
try-lock: every failure path just returns.

## Reading

```c
void f(volatile uint32_t *word, unsigned char flag, unsigned char gen)
{
    // gs:0x58 -> slot -> object, object+0x1294 = this thread's slot index
    uint32_t cur = *word;
    uint32_t mine = (slot << 28) + 0x10000000;
    if (flag) {                                   // generation-checked try
        if (((cur >> 8) & 0xff) < (cur & ((gen << 25) | 0xff))) return;
    } else if (cur & (1u << 25)) {                // already reserved
        return;
    }
    for (;;) {                                    // cmpxchg retry
        uint32_t seen = cur;
        uint32_t got = cmpxchg(word, seen, seen | mine);
        cur = got;
        if (got == seen) break;
    }
    g_slots[slot](1);                             // tail call
}
```

Field layout inside the word: bits 28..31 slot, bit 25 "reserved", bits 8..15
generation, low byte a generation stamp.

## Evidence

Needs a TEB, so `revi call` grew `REVI_GS=1` (sets `ARCH_SET_GS` to a fabricated
TEB with the two indirections the function uses).

| word | flag | result |
|---|---|---|
| `0x00000002` | 1, gen 1 | returns, word unchanged (generation 1 < stamp 2) |
| `0x02000000` | 0 | returns, word unchanged (bit 25 already set) |
| `0x00000000` | 0 | reservation succeeds, then faults at the handler tail call |

The third case faults because `g_slots[0]` is null in an uninitialised image —
the CAS ran, the handler is the part that needs startup.

## Codegen

15%, 37 instructions against 44. MSVC keeps the working word in `rsi` (hence the
`push rsi`) and re-reads it each attempt; ours holds it in a register and the
loop shape differs. Three shapes would not close this; the semantics are pinned
by the run, placement is not.

## Open

* What are the four bits at 28..31? Probably a per-thread owner index; the TLS

* `g_slots` (0x7921fc0) and the handoff at 0x2a1be0, inside `0x2a1af0` both need reading.
