# 0x0066b380

0x25 bytes. Clears an owned child's state and then a flag on the owner. Reached
only through pointer tables, so it is a virtual method (`this` in RCX, never
called directly).

```
push rsi ; sub rsp,0x20 ; rsi = rcx
rcx = [rcx+0x30]        ; owner->child
call sub_1530dc70       ; child->field_0x10
rcx = rax ; edx = 0
call sub_0b844a0        ; notify_state(child_field, 0)
[rewrite byte [rsi+0x41] = 0
epilogue
```

## Reading

```cpp
void f(owner *o)
{
    notify_state(get_child_field(o->child), 0);   // 0xb844a0(obj, 0)
    o->flag_0x41 = 0;
}
```

`0xb844a0(obj, v)` is the state setter: if `obj+0x154` already equals `v` it
does nothing, otherwise it stores `v`, calls `0xb85100(obj, 0xe1a806a2)` and
tail-calls `0x669ec0(obj)`. So this body is "take the child out of its active
state, then drop the owner's flag", i.e. a detach or teardown path.

## Evidence

No direct callers: four base-relocation pointers at `0x161b4e28`,
`0x161b4ec8`, `0x161bb6b8`, `0x161bb7a8` — the method sits in four vtables, which
is what makes the `this` type plausible without guessing.

`0x1530dc70` is itself an interior entry (`0x1530dc40 + 0x30`) whose whole body is
`return this->field_0x10`.

## Codegen

Drafted from the disassembly. `a0` stays opaque; offsets 0x30 (child) and 0x41
(flag) are what the body touches.
